# Webフロントエンドの保守方法

Web UIはブラウザ上で単一のアプリケーションクロージャ（`runApp`）を使用しています。
既存の動作、イベント登録順、スコープを維持しながら機能別に保守できるよう、製品版の編集元を11個のソース断片へ分割しています。

- 製品版の編集元：`src/event_logger/web/frontend/parts/*.jsfrag`
- 製品版の生成物：`src/event_logger/web/static/app.js`

断片を個別に実行することはできません。ファイル名の番号順に結合することで、ブラウザが読み込むIIFEと`runApp`のスコープが復元されます。
07～10番は画面遷移・ログ、設定・OUT管理、ウィジェット編集、起動時初期化のイベント登録を担当します。イベント登録順序が動作へ影響するため、断片の並べ替えや登録順の変更は避けてください。

## 編集と検証

1. 対応する`*.jsfrag`を編集します。生成物の`app.js`は直接編集しません。
2. リポジトリ直下で `node packaging/build_frontend.cjs` を実行して製品版の生成物を更新します。
3. `node packaging/build_frontend.cjs --check` で生成物と編集元が一致することを確認します。
4. `node --check src/event_logger/web/static/app.js`、既存のWeb回帰テストを実行します。

`widget_config.js`は製品版のみで使用する独立したウィジェット設定の変換モジュールです。
`refresh_policy.js`はAPI更新の直列化、ダッシュボード・ログの更新条件、操作中タイムラインの再描画抑止を担当します。
`storage_policy.js`はストレージ警告判定、容量表記と警告表示文を担当します。
`time_format.js`は設定されたタイムゾーンに基づく日時の解析・表示変換を担当し、現在の設定を取得する関数をUIから受け取ります。
`retention_policy.js`は記録保持期間の選択値とAPI応答値を変換し、無期限の`null`を維持します。
`csv_format.js`はデモCSVの列と文字列のエスケープを扱います。実機CSVのHTTP配信はPython側で従来どおり実施します。
`query_policy.js`はダッシュボード・ログ検索のAPIクエリ構築とウィジェットからのログ絞り込みを担当します。
`view_format.js`は画面内で利用するHTMLエスケープと信号・チャンネル名の整形を担当します。
これらの独立モジュールは断片の結合対象外です。変更時は独立ファイルを編集し、テンプレートで`app.js`より前に読み込まれることと、対応するNode.js回帰テストを確認してください。
過去のデモ配布物は現行の配布用リポジトリから除外されており、本ビルドの対象外です。

生成スクリプトと断片の整合性はGitHub Actionsでも検証します。
